迁移方案对比

选择适合项目情况的迁移策略

A. 组件映射迁移法 ⭐ 推荐

逐模块迁移，将 Element Plus 组件直接映射为 Ant Design Vue 组件

迁移映射示意
旧 (Element Plus)新 (Ant Design Vue)
el-tableVXE Table / a-table
el-form + rulesVbenForm + Zod
el-dialoga-modal / Drawer
el-uploada-upload
el-select (远程)ApiSelect
自定义 PaginationVXE Table 内置分页

优势

  • 迁移路径清晰，风险低
  • 可逐模块交付，快速见效
  • 充分利用新框架的表单/表格能力
  • API 层几乎不用改

注意

  • 需要理解 VbenForm schema 配置
  • 部分复杂交互（如设备详情）需重新设计

B. 先搭骨架再填充

先创建所有模块的路由、页面骨架和 API 层，再逐个实现功能

执行步骤
Phase 1: 创建路由 → API 层 → 类型定义
Phase 2: 创建页面骨架（表格 + 搜索表单）
Phase 3: 填充每个模块的业务逻辑

优势

  • 全局视角，模块间依赖先解决
  • 骨架搭好后可并行开发

注意

  • 前期无可见成果
  • 骨架设计如果不当，返工成本高

C. 功能切片迁移

按功能类型（列表 → 弹窗 → 导入 → 详情）而非按模块迁移

执行顺序
📋 所有模块的列表页 → 所有模块的搜索表单 → 所有模块的弹窗 → 批量导入 → 设备详情

优势

  • 同类型代码模式统一
  • 每一步只关注一种交互模式

注意

  • 每个模块都没法独立完成
  • 用户体验上进度不明显
